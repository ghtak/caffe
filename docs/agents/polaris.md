# POLARIS — Agent-Native Engineering Principles

> **"사람은 해결할 문제와 지켜야 할 약속을 정한다. 에이전트는 그 범위에서 변경을 수행하고 결과를 검증한다. 팀은 반복되는 실패와 개입에서 배워 다음 작업의 환경을 개선한다."**

> **"경계는 코드와 도구로 잠그고, 내부는 자율에 맡기며, 코드베이스 자체가 살아있는 교본이 되게 한다."**

> **"같은 품질 기준을 지키면서, 팀이 에이전트에 변경을 맡길 때마다 반복해서 설명하고 확인해야 하는 일이 줄고 있는가"**

이 문서는 AI 에이전트와 협업하는 소프트웨어 엔지니어링의 최상위 방향성과 판단 기준(North Star)을 정의한다. 세부 지침(`AGENTS.md`, 스킬, 린터 설정)은 프로젝트와 도구에 따라 변할 수 있으나, 아래 여섯 가지 대원칙은 흔들리지 않는 기준점으로 삼는다.

---

## 1. Core Thesis: Agent as Code
소프트웨어 공학은 인간의 수작업과 자연어 문서를 결정론적 코드로 편입시키며 진화해 왔다.
- **Service as Code:** 비즈니스 절차서의 코드화 (애플리케이션 로직)
- **Infra as Code:** 서버 세팅 매뉴얼의 코드화 (Terraform, Docker, K8s)
- **Agent as Code:** 에이전트 협업 규칙과 통제 환경(Harness)의 코드화
- **Agent builds the Harness:** 정의된 불변식을 강제하는 검증 도구 자체를 에이전트로 생성

에이전트의 코드 생성 능력은 본질적으로 **확률적(Probabilistic)**이다. 따라서 이를 수용하고 검증하는 작업 환경은 반드시 **결정론적(Deterministic)**이어야 한다. 자연어로 에이전트를 설득하려 하지 말고, 통과할 수밖에 없는 구조와 도구를 코드로 설계한다.

---

## 2. Hard Guardrails, High Freedom (강한 가드레일과 높은 자유도)
에이전트에 대한 미세 통제(Micromanagement)는 프롬프트 비대화와 자의적 해석(Behavioral Drift)만 낳는다. 통제와 위임의 경계를 명확히 나눈다.

- **강한 가드레일 (고정 영역 — 도구로 강제):**
  - 아키텍처 경계 및 의존성 방향 (예: Feature 간 직접 참조 금지, 계층 단방향성)
  - 데이터 스키마, 도메인 불변식(Invariant), 인터페이스 계약(타입·시그니처)
  - 빌드, 정적 분석(Linter/Compiler), 테스트 통과 기준
- **높은 자유도 (위임 영역 — 에이전트 자율):**
  - 고정된 경계와 계약을 만족시키는 내부 상세 구현
  - 로컬 알고리즘 선택, 내부 헬퍼 함수 분리, 구현 세부 스타일

울타리(경계)만 단단히 쳐두면, 그 안에서 에이전트가 어떤 방식으로 구현하든 시스템 전체의 구조는 훼손되지 않으며 실패 반경(Blast Radius)도 해당 슬라이스 내부로 국소화된다.

## 3. From Scaffolding to Enforcement (거푸집에서 도구로)
자연어 지침(`AGENTS.md` 등)은 영구적인 헌법이 아니라, 프로젝트 초기(`0 → 1`)에 구조를 잡기 위한 **일시적 거푸집(Formwork)**이다.

1. **초기 구축기:** 자연어 지침을 거푸집 삼아 첫 디렉토리 구조와 핵심 도메인 슬라이스를 정석대로 세운다.
2. **안정화 및 이관기:** 코드베이스가 궤도에 오르면, 문서에 적었던 제약 사항들을 **컴파일러, 엄격한 타입 시스템, 아키텍처 린터(Boundary rules), 자동화 테스트**로 이관한다.
3. **유지보수기:** 도구로 강제할 수 있게 된 규칙은 문서에서 과감히 걷어낸다. 성숙한 프로젝트일수록 설명 문서는 얇아지고 코드와 도구의 강제력만 남는다.

## 4. Code as Exemplar (코드 자체가 살아있는 모범 답안)
LLM은 본질적으로 컨텍스트에 노출된 패턴을 가장 충실하게 모방하는 패턴 매처(Pattern Matcher)다. 백 마디 규칙 설명보다 **잘 가꾸어진 코드 한 조각(Golden Example)**이 훨씬 강력한 Few-shot 프롬프트로 작동한다.

- **모범 슬라이스 구축:** 아키텍처의 의도가 온전히 담긴 1~2개의 표준 도메인(예: `features/auth`, `features/product`)을 정성껏 가꾸어 둔다. 이후 에이전트는 새로운 기능을 추가할 때 별도 설명 없이도 해당 파일 구조, 네이밍, 데이터 흐름을 그대로 복제한다.
- **깨진 유리창 방지 (Broken Windows):** 초기 코드에 타협이나 나쁜 패턴이 섞이면 에이전트는 그 패턴마저 학습해 프로젝트 전역으로 증폭시킨다. 코드를 깔끔하게 가꾸는 행위는 미학이 아니라 **에이전트의 다음 출력 품질을 결정하는 핵심 투자**다.
- **Code-as-Spec:** 구현과 괴리되기 쉬운 외부 문서 대신, 정돈된 타입 정의와 계약 스텁(`todo!()`) 자체가 곧 명세가 되도록 유지한다.

## 5. Executable Specification & Test Authority (실행 가능한 명세와 권한 분리)
외부 문서는 구현이 진행될수록 코드와 괴리(Drift)된다. 요구사항과 불변식은 별도의 문서가 아니라 **코드 자체(타입 시그니처와 검증 테스트)**로 표현하여 살아있는 명세(Code-as-Spec)로 유지한다.

이때 테스트는 검증 목적에 따라 세 계층으로 분리하고, 계층별로 에이전트의 수정 권한을 다르게 부여한다.

- **`contract` (외부 약속 · 불변 명세):**
  - 호출자에게 보장한 정상 동작, 입력 제약, 보장된 경계값, 오류 규약을 검증한다.
  - **권한:** 승인 필수. 에이전트가 기대 동작을 임의로 변경·약화·삭제할 수 없다. (구현이 실패하면 명세가 아니라 구현을 고친다.)
- **`edge` (구현 방어 · 자율 영역):**
  - 내부 표현 한계, 방어적 입력 처리, 의존성 장애 대응을 검증한다.
  - **권한:** 자율 위임. 에이전트가 구현에 맞춰 자유롭게 추가·수정·삭제한다.
- **`regression` (역사적 불변식 · 영구 봉인):**
  - 실제 발생한 버그의 재현 조건을 검증한다.
  - **권한:** 재현 테스트 추가는 자율이나, 수정 완료된 이후의 기대 동작 약화·삭제는 승인을 거친다.

> **경계값 분류 기준:** 호출자에게 보장하기로 합의한 범위라면 `contract`에, 저장소나 내부 구현의 물리적 한계에서 비롯된 방어라면 `edge`에 둔다.

## 6. Evidence-Based Verification (실행 기반의 신뢰할 수 있는 검증)
에이전트의 완료 보고("구현했습니다", "정상 동작할 것입니다")는 검증이 아니다. 코드가 컴파일되고 단위 테스트를 통과하는 것을 넘어, **실제 제품이 의도대로 구동되는지 확인하는 닫힌 검증 루프(Closed-loop Verification)**를 구축한다.

- **관측 가능성 도구 제공 (Verifiable Harness):**
  - 에이전트가 코드를 수정한 뒤 실제 제품을 기동하고 정상 케이스를 직접 확인할 수 있는 실행 수단(CLI 커맨드, API 호출 스크립트, 헤드리스 브라우저/E2E 러너, 컨테이너 실행 환경 등)을 프로젝트 내에 표준화해 제공한다.
- **보고(Claim)가 아닌 물증(Evidence) 중심의 완료 기준:**
  - 작업의 종료는 에이전트의 요약 설명이 아니라, **도구가 남긴 객관적 산출물(실행 로그, HTTP 응답 본문, 테스트 리포트, UI 스크린샷/캡처 등)**이 정상 케이스임을 증명할 때 성립한다.
- **자가 진단 및 수정 루프:**
  - 검증 도구의 출력물에 오류나 의도치 않은 상태가 포착되면, 인간이 개입하기 전에 에이전트가 해당 로그와 캡처를 근거로 원인을 추적하고 수정하는 사이클을 먼저 완주하게 한다.
---

## 7. Architect vs. Implementer (역할의 재정의)
AI 시대의 엔지니어링은 직접 벽돌을 쌓는 작업에서, **벽돌이 쌓일 설계도와 안전장치를 구축하는 작업**으로 이동한다.

- **인간 (Architect):** 무엇이 변하지 말아야 하는가(데이터 모델, 모듈 경계, 계약, 검증 기준)를 정의하고, 에이전트가 일할 수 있는 결정론적 작업장(Harness)을 설계한다.
- **에이전트 (Implementer):** 고정된 계약과 가드레일 안에서 가장 빠르고 정확한 구현 경로를 탐색해 빈칸을 채운다.
