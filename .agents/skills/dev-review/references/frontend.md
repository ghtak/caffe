
# 프런트엔드 코드 리뷰 세부 지침

## 1. 컨텍스트 및 실행 환경 확인

- [프런트엔드 구조 가이드](../../../../docs/agents/frontend_structure.md)와 관련 기존 코드·테스트를 확인한다.
- 비교 기준(Base)과 대상 커밋, Node.js·패키지 매니저 버전, 실행 플랫폼과 확인한 브라우저·화면 크기를 기록한다.

---

## 2. 정적 검사 및 테스트·화면 확인

1. **정적 검사(순서대로 실행):** 실패하면 결과와 수정 방향을 보고하고 리뷰를 중단한다.
   - `just conbira-ui-lint`
   - `just conbira-ui-check`
   - `just conbira-ui-build`
   - 프로젝트에 별도 포맷 검사 명령이 있으면 함께 실행한다.
2. **테스트 및 화면 확인:**
   - 변경과 관련된 자동 테스트를 실행하고 실패한 테스트의 이름·원인·영향과 수정 방향을 기록한다(테스트 명령이 없으면 사유와 미확인 범위 기록).
   - UI 변경은 가능한 환경에서 정상·로딩·빈 결과·오류 등 해당되는 상태와 주요 사용자 흐름을 확인한다.
   - 키보드 사용과 변경에 관련된 화면 크기도 확인하며, 실행하지 못한 테스트·브라우저·화면 크기와 상태는 사유와 함께 미확인 범위에 기록한다.

## 4. 아키텍처 일관성 질문 관점 (프런트엔드)

- **관점** — 화면 정책, 서버 캐시, URL·폼·UI 상태의 소유자는 누구인가? 정책이 바뀌면 여러 화면이나 훅에서 같은 판단을 수정해야 하는가?
- **계층** — 라우팅·기능 간 화면 조합·도메인 화면·데이터 접근이 각각 `app`, `features`, `shared` 내 적절한 위치에 있는가? UI가 데이터 접근 책임을 직접 떠맡는가?
- **경계** — 의존 방향이 프런트엔드 구조 가이드에 맞는가? 기능 간 직접 의존이나 `shared`의 도메인 의존이 생겼는가? 라우트·컴포넌트·데이터 계약 변경은 어느 호출자와 사용자 흐름에 영향을 주는가?

## 5. 코드 밀도 및 과잉 설계 점검 (프런트엔드)

- **파생 상태 복제 및 불필요한 효과 동기화:** 서버 캐시(TanStack Query), URL 파라미터, 폼 상태에서 렌더링 중 직접 계산 가능한 값을 `useState`와 `useEffect`로 복제·동기화하는 코드.
- **불필요한 중간 추상화:** 재사용 근거 없는 단일 화면용 커스텀 훅 분리, props를 그대로 전달하는 1:1 래퍼 컴포넌트, 이미 경계에서 검증된 타입에 대한 내부 컴포넌트 중복 방어.
- **비동기 상호작용 경합 누락:** 버튼 연타·이중 제출 방지가 없거나, 인증 토큰·일회성 인가 상태를 불필요하게 브라우저 영구 저장소(`localStorage`)에 남기는 처리.
- **구현 세부사항·합성 테스트 비대화:** 사용자 동작과 화면 계약이 아닌 내부 훅 호출 횟수·스타일 클래스명·라우터 기본 동작을 검증하거나, 여러 독립 시나리오를 하나의 거대 테스트 함수에 몰아넣은 경우.
