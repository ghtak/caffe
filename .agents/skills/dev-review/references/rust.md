# Rust 코드 리뷰 세부 지침

## 1. 컨텍스트 및 실행 환경 확인

* 아키텍처·코딩 컨벤션 문서 및 인접 기존 슬라이스(레퍼런스 구현)를 확인한다.
* 비교 기준(Base)과 대상 커밋, Rust·Cargo 버전, 실행 플랫폼과 검사에 사용한 `feature`를 기록한다.
* 변경과 관련된 지원 `feature`·플랫폼은 추가 검사하고, 실행하지 못한 조합은 사유와 함께 미확인 범위에 기록한다.

---

## 2. 정적 검사 및 테스트 실행

1. 정적 검사(순서대로 실행): `fmt` 또는 `clippy` 실패 시 결과와 수정 방향을 보고하고 리뷰를 중단한다.
   * `cargo +nightly fmt --all -- --check` (종료 코드 0)
   * `cargo clippy --workspace --all-targets --locked -- -D warnings` (종료 코드 0, 경고 없음)
   * `cargo audit` (종료 코드·advisory를 알림으로 기록, 리뷰 차단 안 함)
2. 테스트 실행:
   * `just test` 실행 후 실패한 테스트의 이름·원인·영향과 수정 방향을 기록한다.
   * `ignored` 테스트와 외부 서비스가 필요한 테스트의 실행 여부를 확인하고, 실행하지 못했다면 사유와 미확인 범위에 기록한다.
   * 변경과 관련된 추가 `feature`·플랫폼 조합도 테스트하고 실행하지 못한 조합은 사유를 기록한다.

## 4. 아키텍처 일관성 질문 관점 (Rust)

* 관점 — 이 정책이 바뀌면 어느 주체가 판단을 수정해야 하는가? 새 호출자가 같은 결정을 다시 내리는가?
* 계층 — 이 처리가 현재 계층의 역할에 맞는가? 기존 책임을 우회하거나 여러 계층에 분산하는가?
* 경계 — 새 의존이나 데이터 접근으로 어느 모듈이 다른 모듈의 내부 변경에 영향을 받는가? 공개 계약과 데이터 소유권을 따르는가?
* 관례 — 인접한 기존 슬라이스의 모듈 구조, 네이밍, 에러·트랜잭션 처리 방식을 따르는가? 근거 없이 독자적인 패턴을 새로 도입했는가?

## 5. 코드 밀도 및 과잉 설계 점검 (Rust)

* 신뢰 경계 초과 검증: 이미 서명 검증을 통과한 외부 토큰 클레임이나 크레이트 타입(`Url` 등)이 보장하는 스펙을 정규식·문자열 분리로 재검증하는 코드.
* 불필요한 중간 추상화: 1회용 에러 생성 함수·클로저, 1:1 패스스루 래퍼, 실패 흐름을 숨기는 `Ok(Outcome::Failed)` 열거형, 이미 고유한 식별자(UUID·CSRF 토큰)에 대한 중복 해싱.
* 동기화 락·트랜잭션 점유 범위: `Mutex`, `RwLock`, 세마포어 퍼밋 등 동기화 락(또는 DB 트랜잭션)을 점유한 채 네트워크·디스크 I/O(`.await`)를 수행해 다른 태스크의 정상 경로를 블로킹하거나 경합·데드락을 유발하는 구간.
* 합성 테스트 비대화: 도메인 계약이 아닌 서드파티 메타데이터 오작동 모킹이나 과도한 헤더·쿼리 퍼징성 에지 케이스로 테스트가 본문보다 비대해진 경우.
