# 프런트엔드 구현 세부 지침

## 1. 사전 파악 (프런트엔드 특화)

- 작업 전 [프런트엔드 구조 가이드](../../../../docs/agents/frontend_structure.md)를 읽어 프로젝트 레이어 구조, 의존성 경계, 상태 관리, 스타일링 기준을 확인한다.

## 2. Phase 1. 화면·상태 계약 및 정적 시안 기준

- 계약 정리: 라우트·레이아웃·컴포넌트별 상태 소유권과 함께 입력·출력, URL 파라미터, API 계약, 로딩·빈 결과·오류 상태, 기본 접근성, 주요 인터랙션 식별자(`data-testid`)를 정의한다.
- 정적 시안: 의존성 경계를 지키는 타입·인터페이스와 컴포넌트 골격 및 대표 상태를 확인할 수 있는 정적 시안을 작성한다(예시 데이터·미동작 요소는 리뷰 시 명시).
- 정적 확인: 타입 검사와 import 경계만 확인한다.

## 3. Phase 2. 상세 구현 및 검증 기준

- 상태 소유권 및 구조 밀도:
  - 서버 상태, 전역 UI 상태, URL 상태, 로컬 입력 상태의 소유권을 명확히 분리하고 불필요한 파생 상태(`useEffect` 동기화 등)나 상태 복제를 만들지 않는다.
  - 1회성 단순 래퍼 컴포넌트나 단일 호출부 커스텀 훅으로 흐름을 파편화하지 않는다.
- UI 식별자(`data-testid`): 아이콘 전용 버튼, 동적 리스트 행, 복합 패널 등 가시 텍스트나 ARIA 역할만으로 특정하기 어려운 핵심 인터랙션 요소에 한해 `<domain>-<component>-<element>` 형식으로 부여한다(정적 텍스트·단순 래퍼 남발 금지).
- 도구 및 화면 검증:
  - 프로젝트의 타입 검사·린트·빌드·테스트 명령을 실행해 통과를 확인한다.
  - 가능한 환경에서 실제 화면(로딩·빈 결과·오류·주요 동작)을 확인하고, 확인하지 못한 화면이나 상태는 결과에 명시한다.
