# Rust 테스트 지침

Rust 소스 파일 안에 테스트를 추가·수정할 때 `#[cfg(test)] mod tests` 아래에 `mod contract`, `mod edge`, `mod regression` 중 해당 테스트가 있는 하위 모듈만 선언. 기존 모듈 관례에 따라 테스트 코드는 모듈 하단에 배치.

경계값은 호출자에게 보장한 범위를 기준으로 분류. API가 양의 정수 밀리초 TTL을 요구하면 `1ms` 미만 입력 거절은 `contract`. 저장소의 표현 한계로 정해진 TTL 상한은 `edge`에 두고, API가 그 상한까지 보장하면 `contract`로 분류.

## 테스트 변경 승인

- `edge` 테스트는 에이전트가 추가·수정·삭제할 수 있음. 요청받은 버그의 재현 테스트도 추가 가능.
- 기존 계약 테스트와 수정이 완료된 버그의 회귀 테스트는 기대 동작을 바꾸거나 검증을 약화·제거하기 전에 사용자 승인 필요. 테스트 비활성화, 모듈 이동, 공용 헬퍼 변경으로 검증 범위가 줄어들 때도 적용.
- 검증 조건과 기대 결과를 유지하는 이름·구조 변경은 자율적으로 진행. 사용자가 기대 동작 변경을 명시적으로 요청한 경우 해당 범위의 테스트 변경도 승인된 것으로 봄.
