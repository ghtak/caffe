# 프런트엔드 테스트 지침

## 검증 목적과 배치

- `contract`: 합의된 화면·상태 계약과 사용자 흐름. 예를 들어 목록을 불러오는 동안 로딩을 표시하고, 빈 응답에는 빈 화면을, 요청 실패에는 안내와 재시도 동작을 제공하기로 했다면 해당 동작을 검증.
- `edge`: 화면 계약에서 직접 다루지 않는 입력 방어와 예외 상황. 예를 들어 이전 검색의 응답이 늦게 도착해 최신 검색 결과를 덮어쓰지 않는지 검증. 경쟁 요청 처리 자체가 합의된 화면 동작이면 `contract`로 분류.
- `regression`: 실제 UI 버그를 일으킨 입력·동작 순서·응답을 재현. 예를 들어 저장 버튼을 빠르게 두 번 눌렀을 때 중복 등록됐던 버그를 같은 조건에서 검증.

파일 배치와 그룹화는 기존 테스트 관례를 따름. 테스트 러너가 그룹을 지원하고 별도 관례가 없으면 `describe("contract")`, `describe("edge")`, `describe("regression")` 중 해당 사례가 있는 그룹만 사용.

## 작성 및 확인

- 사용자 입력, 화면에 표시되는 결과, 탐색과 포커스 등 관찰 가능한 동작을 검증. 접근 가능한 이름이나 역할을 우선 사용하고, 관련 변경에 한해 키보드 흐름을 확인.
- 변경에 해당하는 정상·로딩·빈 결과·오류 상태를 선택. 서버 응답이나 실패 시점 제어가 필요하면 API 경계에서 응답을 대체하고 화면 결과를 검증.
- 저장소에 자동 테스트 환경이 있으면 해당 명령으로 검증. 환경이 없으면 가능한 범위에서 실제 화면과 사용자 흐름을 확인하고, 실행한 검사와 미확인 범위를 기록. 타입 검사·린트·빌드는 별도로 기록.
