# 즉시 구현 워크플로우

## 1. 적용 기준

- **사용**: 구현 대상·입출력·동작이 명확한 작업 (예: 기존 테이블 조회 API 추가, 파라미터·필터·페이징 추가, 단순 화면 연동, 명확한 버그 수정).
- **제외 (`dev-impl` 전환)**: 신규 도메인/화면 설계, 공개 계약 미확정, 다단계 풀스택 조정, 고위험 권한·데이터 변경.
- **중단 원칙**: 구현 중 기존 계약과 충돌하거나 모호한 정책(권한, 정렬/기본값, 에러 코드 등)이 커지면 임의 추측하지 않고 즉시 확인 요청.

---

## 2. 실행 절차 (3단계)

### Step 1. 최소 파악

1. 대상 스택 지침 로드 (Phase 2·구조 관례 기준만 적용, Phase 1 스텁 단계 생략):
   - Rust 백엔드: [Rust 구현 지침](../dev-impl/references/rust.md), [Conbira 모듈 구조 관례](../dev-impl/references/conbira.md)
   - 프런트엔드: [프런트엔드 구현 지침](../dev-impl/references/frontend.md)
2. 기준 코드 확인:
   - 대상 도메인의 기존 코드(이미 존재하는 경우), 라우터 등록 위치, 관련 마이그레이션·테스트 확인.
   - 유사 유스케이스(목록 조회·검색·페이징 등)를 구현한 타 도메인 슬라이스 2~3개와 공용 모듈(요청 추출기, 응답·에러 처리, 쿼리 빌더 등)을 함께 확인해 일관된 관례 파악.

### Step 2. 즉시 구현 및 테스트

1. **명료성 규칙 준수**:
   - 신뢰 경계(핸들러/API 응답)에서 1회 검증·변환하고 내부 로직은 타입을 신뢰.
   - 추측성 `Option`/`?` 확장, 1회성 래퍼 함수, 중복 상태 금지.
   - 기존 크레이트·유틸리티 우선 사용, `?`와 조기 반환으로 선형 흐름 유지.
2. **구현 및 테스트 작성**:
   - 계약 골격 승인 없이 바로 로직·라우팅·화면 구현.
   - [test-guide](../test-guide/SKILL.md) 기준에 맞춰 핵심 정상 경로와 경계 조건(검색어, 페이징 범위 등) 테스트 작성.

### Step 3. 도구 검증 및 요약 보고

1. 스택별 검증 실행 및 통과 확인:
   - Rust: `cargo +nightly fmt --all --`, `cargo clippy --all-targets`, `cargo test` (변경 범위 또는 전체)
   - 프런트엔드: 타입 검사, 린트, 테스트 실행
2. 변경 파일, 핵심 구현 내용, 검증 결과만 간결히 보고 (승인 대기·상태 파일 관리 없음).
