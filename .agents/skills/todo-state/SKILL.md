# 일회용 작업 상태 관리 (`.agent/.state/todo.md`)

`git worktree` 기반 분리된 작업 환경을 가정하며, `.agent/.state/`는 저장소의 `.gitignore`로 추적에서 제외한다.

## 1. 경로 및 파일 포맷 (최대 50줄)
- 상태 파일: `$worktree_root/.agent/.state/todo.md` (워크트리당 1개 고정)
- 누적(Append)을 금지하고 항상 최신 스냅샷으로 덮어쓴다(Overwrite).
- 아래 두 섹션 외에 실행 로그나 상세 스펙을 적지 않는다.
  ```markdown
  ## 계약·가정
  - (확정된 핵심 계약·가정 5줄 이내 요약)

  ## 목록
  - [x] 항목 1 — `근거: 수정 파일 및 검증 결과`
  - [ ] 항목 2 *(진행 중)*
  ```

## 2. 읽기·쓰기 권한 및 생명주기
- 초기화/복구: 작업 시작 시 파일이 있으면 먼저 `## 계약·가정`과 `## 목록`을 읽어 현재 요청과 동일 작업의 연속인지 확인한다.
  - 동일 작업이면 기존 파일을 그대로 복구해 이어간다.
  - 명백히 다른 새 작업이면 임의로 덮어쓰지 않고 미종료 상태인 이전 작업의 존재를 알린 뒤, 폐기 후 새 작업으로 초기화할지 사용자 확인을 받는다.
  - 파일이 없으면 최초 작업 분할 직후 생성한다.
- 권한 분리:
  - 구현 세션(Single Writer): 파일을 읽고 수정한다. 상태 변경 시 대화 기억 대신 파일을 먼저 읽은 뒤 덮어쓴다.
  - 독립 리뷰 세션(Read-Only): 파일 수정 없이 `## 계약·가정`과 `## 목록`을 읽어 검토 기준으로만 활용한다.
- 목록 유지 규칙: 최초 항목의 이름·순서를 고정하고, 요구사항 변경 시에만 항목을 추가하거나 사유를 명시해 조정한다. 완료 항목 재검증 시 미완료(`재진행 중`)로 되돌린다.
- 폐기: 사용자가 전체 작업 완료를 명시적으로 확정하거나 작업 종료(중단)를 선언할 때만 `rm -f .agent/.state/todo.md`로 삭제한다(단계 승인·리뷰 통과·커밋만으로는 삭제 금지).

## 3. 응답 출력 규칙
- 매 턴 상시 출력: 모든 응답 최하단에 `## 목록`에서 상세 근거(`— 근거: ...`)를 생략한 간략 상태만 출력한다. 모든 개별 항목 완료 후에도 `작업 완료` 자동 체크를 금지한다(`완료 확인 대기` 유지).
  ```text
  📌 작업 목록 (`.agent/.state/todo.md`)
  * [x] 작업 항목 1
  * [ ] 작업 항목 2 *(진행 중)*
  * [ ] 작업 완료 *(완료 확인 대기)*
  ```
- 최종 보고·종료 출력: 완료 보고, 전체 작업 완료 확정, 작업 종료 선언 시에는 `.agent/.state/todo.md`의 상세 근거(`— 근거: ...`)를 포함해 출력한다.
